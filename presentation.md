# VehicleLogger
## Система мониторинга фур в реальном времени

Курсовой проект · 2026

> 📷 *ФОТО: общий вид собранного устройства / логотип*

---

# О проекте

**Проблема.** Владельцы автопарков не видят, что происходит с фурой между рейсами: расход топлива, обороты двигателя, ошибки ECU, маршрут. Контроль идёт «по бумажке» от водителя.

**Решение.** Аппаратный модуль в кабине читает CAN-шину автомобиля, отправляет телеметрию на сервер. Админ компании видит данные на веб-панели в реальном времени, водитель — управляет своей фурой через Telegram-бота.

**Актуальность.**
- Российский рынок — 1.5 млн коммерческих грузовиков, 80% работают без телематики
- Импортозамещение: западные системы (Wialon, Omnicomm) дороги или недоступны
- ESP32 + open-source стек → ~2000 ₽ железо vs ~30 000 ₽ у конкурентов

> 📷 *ФОТО: статистика рынка / иллюстрация фуры с устройством*

# Архитектура системы

```
┌─────────────────┐    HTTPS      ┌──────────────────────┐
│  ESP32 в кабине │──────────────▶│   Бэкенд .NET 10     │
│  CAN/GPS/IMU    │  /telemetry   │   + SQLite + Vue 3   │
└─────────────────┘               └──────────────────────┘
                                          │
                              ┌───────────┴────────────┐
                              ▼                        ▼
                      ┌──────────────┐        ┌────────────────┐
                      │  Web-панель  │        │ Telegram-бот   │
                      │   (админ)    │        │   (водитель)   │
                      └──────────────┘        └────────────────┘
```

**Три независимых компонента**, общающихся через REST API.
Мультитенантность: каждая компания = свой поддомен `<sub>.nonconf.ru`.

# Этап 1: Диагностика модулей

Первое, что делает прошивка после сборки — проверяет каждый сенсор.

```
TEST 1: Wi-Fi          → OK    (RSSI -45 dBm)
TEST 2: I2C / MPU-6050 → OK    (WHO_AM_I 0x68, ax/ay/az читаются)
TEST 3: CAN / TWAI     → OK    (driver installed @ 500 kbit/s)
TEST 4: GPS / NEO-M8N  → OK    (NMEA, 8 спутников видно)
```

Если что-то не работает — сразу видно по boot-логу в Serial Monitor, без отладчика.

# Этап 2: Два мира CAN

| | **SAE J1939** | **OBD-II (ISO 15765-4)** |
|---|---|---|
| ID | 29-бит (extended) | 11-бит (standard) |
| Скорость | 250 кбит/с | 500 кбит/с |
| Модель | **Broadcast** — ECU сам шлёт PGN | **Запрос-ответ** на 0x7DF |
| Где | Грузовики, автобусы (MAN, Volvo Trucks, Scania, КАМАЗ) | Легковые ≥ 2008 г. (Volvo S80, Toyota, …) |
| Адресация | Source Address в ID | ECU отвечает на 0x7E8–0x7EF |

**Прошивка поддерживает оба** — определяет автоматически.

# Этап 2: OBD-II поллер для легковых

J1939 на легковой не работает. Volvo S80 G2 2009 — на нём 7 PID-ов:

| PID | Параметр | Формула |
|-----|----------|---------|
| 0x04 | Engine load | A × 100 / 255 |
| 0x05 | Coolant temp | A − 40 |
| 0x0C | RPM | (A·256 + B) / 4 |
| 0x0D | Speed | A |
| 0x2F | Fuel level | A × 100 / 255 |
| 0x42 | Voltage | (A·256 + B) / 1000 |
| 0x5E | Fuel rate | (A·256 + B) / 20 |

ESP отправляет запросы на `0x7DF` (functional broadcast) с интервалом 100 мс по очереди для каждого PID, ловит ответы на `0x7E8–0x7EF`.

# Этап 2: Авто-определение шины

ESP не знает заранее, к чему его подключили — фура или легковая. **State machine** разруливает:

```
                BOOT
                  │
                  ▼
        ┌─ Listen-only @ 500 kbit/s ─┐
        │                              │
        │   3 сек — есть 29-бит?      │
        │       │              │       │
        │       │ да           │ нет   │
        │       ▼              ▼       │
        │   J1939            500 → 250 │
        │   (listen-only)              │
        │                              │
        │   3 сек — есть кадры?        │
        │       │              │       │
        │       │ да (только   │ нет   │
        │       │ 11-бит)      ▼       │
        │       ▼          NORMAL @ 500│
        │   OBD-II         (default    │
        │   (NORMAL +       OBD-II)    │
        │    poll 0x7DF)               │
        └──────────────────────────────┘
```

Один и тот же бинарник работает на любом авто.

# Этап 2: Стенд верификации

Пока зимой не получилось снять данные с реальной машины — сделал стенд на **USBCAN-2A** (анализатор CAN-шины) + Python-скрипты:

- `tools/j1939_send.py` — генерирует 9 PGN с реалистичными значениями фуры на холостом
- `tools/obd2_emu.py` — эмулирует ECU Volvo S80, отвечает на запросы 0x7DF

USBCAN-2A работает на **обоих каналах одновременно** в режиме NORMAL — каналы ACK-ают друг друга, ESP сидит в LISTEN_ONLY и видит весь обмен.

# Этап 3: Идея — мультитенантность через поддомены

Каждая компания получает свой поддомен `<sub>.nonconf.ru` (wildcard-сертификат `*.nonconf.ru`):

| URL | Кто заходит | Что видит |
|-----|-------------|-----------|
| `nonconf.ru` | Super-admin платформы | Все компании, регистрация новых |
| `acme.nonconf.ru` | Admin компании ACME | Только свои фуры/устройства/водителей |
| `volvo.nonconf.ru` | Admin компании Volvo | Только свои фуры/устройства |

**Изоляция данных** на уровне URL: `tenant_id` подмешивается во все запросы middleware'ом по `Host`-заголовку. SQL-выборки автоматически фильтруются.

# Этап 3: Поток установки устройства

Старый подход (отвергнут): QR-код на корпусе + claim через web после сканирования. Сложно, требует смартфон с интернетом и логин в систему.

**Новый подход — атомарная привязка через 6-значный код:**

```
1. Админ компании в ЛК → «Добавить устройство» → выдаётся код 428193 (TTL 30 мин, single-use)
2. Установщик в фуре подключает ESP32 → автоматически поднимается SoftAP "VehicleLogger-XXXX"
3. Подключение телефоном (пароль setup1234) → captive portal на 192.168.4.1
4. Ввод: WiFi-сеть + пароль + поддомен компании + 6-значный код
5. ESP подключается к WiFi → POST https://<sub>.nonconf.ru/api/devices/enroll
6. Backend: проверка serial+secret+code → выдача API-ключа
7. ESP сохраняет ключ в NVS → перезагрузка → рабочий режим
```

**Один запрос, никакого QR, никакого поллинга.**

# Этап 3: Captive portal на ESP32

При первом включении ESP поднимает Wi-Fi точку доступа `VehicleLogger-XXXXXXXX` и отдаёт минимальную HTML-страницу (~6 КБ из LittleFS):

- DNS catch-all (любой запрос → редирект на 192.168.4.1)
- Async WebServer + JSON API: `/api/scan`, `/api/setup`, `/api/status`, `/api/info`
- State machine: ввод → connect WiFi → POST enroll → результат
- Маппинг ошибок: `invalid_code` / `invalid_subdomain` / `already_claimed` / `network_error` — каждая со своим сообщением в UI

> 📷 *СКРИН: captive portal в Chrome на телефоне с заполненными полями*

# Этап 3: Хранение в NVS

Прошивка одна для всех устройств. Различия — в NVS:

| Namespace | Ключ | Откуда |
|-----------|------|--------|
| `factory` | `serial` (`VL-XXXXXXXX`) | Заводской скрипт (генерится из MAC) |
| `factory` | `secret` (32 байта) | Заводской скрипт (random) |
| `wifi` | `ssid` / `password` | Captive portal |
| `cloud` | `api_key` | Ответ `/enroll` |
| `cloud` | `backend_url` | Ответ `/enroll` |

**Boot state machine** решает по NVS:
- Пусто → SoftAP (captive portal)
- Есть WiFi+ключ → рабочий режим (телеметрия)
- Есть WiFi, нет ключа → SoftAP (предыдущий enroll не удался)

# Этап 3: Backend Тимура

Тимур реализовал нашу спеку **1:1**:

**Без авторизации (для устройства):**
- `POST /api/devices/enroll` — атомарная привязка
- `POST /api/telemetry` (Bearer api_key) — телеметрия
- `POST /api/device/ping` — heartbeat

**JWT (admin компании):**
- `POST /api/enrollment-codes` — выпуск 6-значного кода
- `GET /api/devices` — список устройств тенанта
- `POST /api/devices/{id}/unclaim` — отвязать
- `POST /api/devices/{id}/rotate-key` — ротация ключа
- `GET /api/vehicles/{id}/telemetry` — история для графиков

**Super-admin (на apex):**
- `POST /api/tenants` — создать компанию

# Безопасность

**Транспорт.** ESP → backend только HTTPS. Wildcard `*.nonconf.ru` (Let's Encrypt).

**API-ключи.** 64-hex (256 бит). Backend хранит только SHA-256 хеш. Plaintext существует только в одном месте — NVS устройства. При компрометации — `/rotate-key`.

**Защита enroll-flow — три фактора:**
1. **Физический доступ** к устройству (для подключения к SoftAP)
2. **Знание поддомена** компании
3. **6-значный код** от админа конкретного тенанта (TTL 30 мин, single-use)

**Защита от опечатки в поддомене.** Код привязан к одному тенанту: ввёл `acne` вместо `acme` → код не пройдёт → ошибка в UI. Устройство **не** привяжется к чужой компании.

**Изоляция БД.** Middleware режет каждый JWT-запрос по `tenant_id` хоста. Запрос на `acme.nonconf.ru` с JWT компании Volvo → 403 `tenant_mismatch`.
